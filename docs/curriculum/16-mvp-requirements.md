# 16 — Требования к MVP

> Фаза 4, часть 4. Продуктовые требования к первой версии LINGUA: сначала тест владельцем проекта, затем небольшая группа учеников. Оплата и подключение API в этой фазе **не реализуются**. Требования сформулированы так, чтобы по ним можно было работать в Claude Code. Приоритеты: **M** — обязательно, **S** — желательно, **C** — можно позже.

## 1. Цели и этапы

| Этап | Кто | Цель | Что должно работать |
|---|---|---|---|
| **Этап 0 — тест владельцем** | владелец проекта | проверить логику диагностики, маршрута и одного полного модуля; проверить расходы на AI | аккаунт, диагностика (14), маршрут (15), пилотный модуль A1-M1 (12), отчёт, учёт расходов |
| **Этап 1 — малая группа** | небольшая группа учеников разных уровней | проверить пользу для учеников, реалистичность 60 минут, надёжность оценки Speaking, пороги | всё из этапа 0 + стартовые модули уровней (§3) + недельный отчёт + 14-дневная повторная оценка + экспертная проверка выборки записей |

**Критерии готовности к этапу 1:** владелец прошёл диагностику не меньше 3 раз в разных ролях (14 §17) и не меньше 6 занятий A1-M1; найденные ошибки логики исправлены; расход AI на одного ученика в день измерен и укладывается в заданный бюджет (§5). Конкретные значения бюджета задаёт владелец; до пилота они — [ГИПОТЕЗА].

## 3. Объём учебного контента в MVP

Контент LINGUA пока существует как **карты и спецификации**. Тексты, аудио и задания ещё предстоит написать.

| Вариант | Содержание | Плюсы | Минусы |
|---|---|---|---|
| **A (этап 0)** | диагностика + A1-M1 полностью (12 занятий) + «Старт» (6 занятий) | минимальный объём; полностью проверяется весь цикл модуля | ученики уровня выше A1 получают только диагностику |
| **B (рекомендуется для этапа 1)** | A + **первые модули половин уровней, куда реально попадут ученики группы**: A2-M1, B1-M1, B2-M1 (и при необходимости A2-M7, B1-M7, B2-M7) | каждый ученик начинает со своего уровня (требование: «B1 не начинает с A1») | 3–6 модулей × 12 занятий контента + аудио |
| **C** | весь уровень A1 | глубокая проверка одного уровня | не подходит группе разных уровней |

**Правило при отсутствии контента (для 15 §11):** если стартовый модуль ученика ещё не готов, система честно сообщает об этом, показывает результат диагностики и маршрут и предлагает ближайший готовый модуль **того же уровня**, а не ниже. **Ученик уровня B1 не направляется в A1** ни при каких условиях.

**Банк диагностики для MVP:** полный банк 14 §12 большой. Для этапа 0 допустим **сокращённый банк** (например, 8 заданий на полосу для Vocabulary и Grammar, 1–2 тестлета на полосу [ГИПОТЕЗА]) с пометкой «пилотная версия». Перед этапом 1 его нужно расширить.

## 5. Ограничение расходов на AI

**Принцип:** AI-модель вызывается только там, где без неё нельзя. Всё остальное делают правила и заранее подготовленный контент.

| Мера | Требование |
|---|---|
| Детерминированная проверка | закрытые и полуоткрытые задания (выбор, ввод, шаблоны) проверяются **без** AI (13 §8) |
| Кэширование | одинаковые ответы на одно задание переиспользуют сохранённую оценку (ContentCache, 13 §14) |
| Сценарные диалоги | Speaking Partner на A1–A2 работает по сценарию с ветвлениями; свободная генерация — только на B1–B2 и с лимитом реплик |
| Объединённая оценка | Speaking оценивается одним вызовом на всю запись части или занятия, а не на каждую фразу; Writing — один вызов на текст |
| Лимит аудио | ограничение минут распознавания речи на занятие и на день (параметр) |
| Дневной и месячный бюджет | AIBudget на ученика или план (13 §14). При исчерпании — **мягкая деградация**: текстовая обратная связь по шаблонам, отложенная оценка Speaking, сценарные диалоги без генерации. Занятие не прерывается |
| Разные классы моделей | простые задачи (короткая обратная связь, классификация ошибок) — более дешёвой моделью; рубричная оценка Speaking и Writing — моделью нужного качества (выбор моделей — при реализации) |
| Отчёты из данных | недельный отчёт и экран прогресса собираются из сохранённых данных; модель пишет только короткое резюме (по желанию) |
| Мониторинг | расход на активного ученика в день, по функциям; предупреждение администратору при превышении порога |

Значения лимитов и бюджета **не задаются здесь** без данных: их нужно измерить на этапе 0 и утвердить владельцу (§10).

## 9. Вне рамок MVP
Оплата и подписка (только подготовка через Entitlement); мобильные приложения; уровни C1–C2; групповые занятия и кабинет учителя; телефонные звонки на A1 (по программе их нет); публичный маркетинговый запуск; подключение внешних AI API в этой фазе.

## 10. Порядок разработки (для Claude Code)
1. **Модель данных и конфигурация** по 13 (+ §14 дополнений) и параметрам 14 §16, 15 §10.
2. **Аккаунты, согласия, удаление** (ACC-1…4, PRV-1…7).
3. **Формат контента** (файлы уроков, заданий, банка диагностики) и загрузчик с версиями (ADM-1).
4. **Плеер заданий и детерминированная проверка** (LSN-2, 13 §8).
5. **Диагностика без AI-частей** (Vocabulary, Grammar, Reading, Listening) + объединение и отчёт.
6. **Запись голоса**, затем интерфейс для AI-оценки Writing и Speaking. Сначала с ручной или экспертной оценкой как заглушкой, без подключения API в этой фазе.
7. **Маршрут** (15) и **банк повторения**.
8. **Занятия A1-M1** по стандарту 11 и карте 12.
9. **Учёт расходов и бюджет** (ADM-3, §5), затем подключение AI-провайдера на следующем этапе.
10. **Отчёты, 14-дневная оценка, экспертная очередь** — для этапа 1.

## 11. Решения, требующие подтверждения владельца
1. **Объём контента для этапа 1:** вариант B (§3) и список модулей, исходя из уровней учеников группы.
2. **Бюджет AI** на ученика в день и месяц, а также правило деградации (§5): значения после измерений этапа 0.
3. **Срок хранения сырого аудио** и срок выполнения запроса на удаление (PRV-3, ACC-4).
4. **Сокращённый банк диагностики** для этапа 0 (§3).
5. **Страна и юрисдикция** первого запуска для правового анализа (PRV-8).
